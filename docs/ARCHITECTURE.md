# ブートキャンプ設計：演奏能力を測り、処方し、積み上げるアプリ

この文書は「指弾きギター練習帖」を、10分の練習日記から**プロ演奏家に必要な能力を体系的に鍛える訓練システム**へ拡張するための全体設計です。
実装ではなく、実装が従うべき構造を定めます。

---

## 1. 設計の出発点

現状のアプリは「レッスン = 固定の文書」です。ユーザーは読み、弾き、チェックを付けます。
ブートキャンプに必要なのは別の構造です。

```
現状:   教材 ──表示──> 人  ──自己申告──> チェックボックス
必要:   能力モデル ──処方──> ドリル ──実演──> 測定 ──更新──> 能力モデル
```

**閉じたフィードバックループが無い訓練は、気合の消耗でしかありません。**
「気合と練習で身につける」を成立させる条件は精神論ではなく、次の3つです。

1. 今どこが弱いかが**数字で見える**
2. 今日やるべきことが**選択の余地なく決まっている**
3. 昨日より進んだことが**客観的に確認できる**

以下の設計は、この3点を満たすための構造です。

---

## 2. 「プロの演奏家に必要な能力」の分解

漠然とした目標は訓練できません。9ドメイン・約40能力に分解し、それぞれに10段階の到達基準を持たせます。
ID は `domain.subdomain.ability` 形式で、ドリルからこのIDを参照します。

### 2.1 技術（`tech`）— 身体が音を出す能力

| ID | 能力 | なぜプロに必要か |
|---|---|---|
| `tech.rh.independence` | 右手各指の独立 | 全ての多声部演奏の前提 |
| `tech.rh.tone` | 音色コントロール（当てる角度・位置・爪と肉） | 「上手い」の正体の大半はこれ |
| `tech.rh.dynamics` | 音量の制御幅と粒の揃い | 表現の物理的な土台 |
| `tech.rh.patterns` | アルペジオ／トレモロ／ラスゲアド | レパートリーの要求 |
| `tech.lh.pressure` | 最小限の押弦圧（脱力） | 速度・持久力・故障予防の全てに効く |
| `tech.lh.shift` | ポジション移動の精度と速度 | 指板全域を使う条件 |
| `tech.lh.barre` | セーハの持続と部分セーハ | 実曲での詰まりの最大要因 |
| `tech.lh.slur` | ハンマリング／プリング／スライド | フレージングの語彙 |
| `tech.sync` | **左右の同期** | 速度の上限を決める真のボトルネック |
| `tech.endurance` | 持続力（連続演奏時の劣化率） | 本番は1曲では終わらない |

> `tech.sync` を独立能力として立てるのが重要です。「速く弾けない」原因は片手の速度不足ではなく、両手のタイミングずれであることがほとんどです。左右を別々に測っても見つかりません。

### 2.2 リズム（`time`）

| ID | 能力 |
|---|---|
| `time.pulse` | 内的パルスの安定（クリック無しでのドリフト率） |
| `time.subdivision` | 細分化の正確さ（8分・3連・16分） |
| `time.accuracy` | グリッドに対する**偏り**（走り／もたり） |
| `time.precision` | グリッドに対する**ばらつき**（揺れ） |
| `time.independence` | 四肢・声の独立（既存 `rhythm.html` の領域） |
| `time.groove` | 意図的な前ノリ／後ノリの制御 |
| `time.rubato` | テンポを崩して戻す制御 |

> `time.accuracy`（偏り）と `time.precision`（ばらつき）を**必ず分けて測ります**。常に15ms走る人と、±15msで揺れる人は、まったく別の問題を抱えていて、処方も違います。平均値だけを見せるアプリは役に立ちません。

### 2.3 聴覚（`ear`）

| ID | 能力 |
|---|---|
| `ear.pitch` | 音程認識・チューニング精度 |
| `ear.interval` | 音程の即答 |
| `ear.harmony` | 和音種別・機能の聴き分け |
| `ear.transcription` | 採譜（聴いて指板に落とす） |
| `ear.selfmonitor` | **演奏中に自分の音を聴く能力** |

> `ear.selfmonitor` が最も軽視され、最も差がつきます。これを鍛える唯一の方法は「録音して聴き返す」であり、アプリの機能として毎回強制すべきものです。

### 2.4 読譜（`read`）

| ID | 能力 |
|---|---|
| `read.staff` | 五線譜の読解速度 |
| `read.sight` | **初見演奏** |
| `read.fretboard` | 指板上の音名の即答 |
| `read.chart` | コードシンボル／リードシート |

> `read.sight` は職業演奏家の生命線です（現場は譜面が当日出ます）。アマチュアが最も飛ばす領域でもあるので、カリキュラムに強制枠を置きます。

### 2.5 理論と即興（`harm`）

`harm.scales` / `harm.chordtones` / `harm.voiceleading` / `harm.progression` / `harm.improv` / `harm.arrange`

### 2.6 レパートリー（`rep`）

| ID | 能力 |
|---|---|
| `rep.memory.motor` | 運動記憶 |
| `rep.memory.aural` | 聴覚記憶 |
| `rep.memory.structural` | 構造記憶（形式・和声で覚える） |
| `rep.maintenance` | 覚えた曲を腐らせない維持力 |
| `rep.breadth` | 演奏可能曲数と様式の幅 |

> 暗譜は単一能力ではなく多層です。運動記憶だけで覚えた曲は本番で一度止まると復帰できません。**「どの小節からでも弾き始められるか」**を構造記憶の測定に使います。

### 2.7 表現（`mus`）

`mus.phrasing` / `mus.agogics` / `mus.dynamics_design` / `mus.timbre_palette` / `mus.form`

### 2.8 本番能力（`perf`）

| ID | 能力 |
|---|---|
| `perf.robustness` | 一発通しの完遂率 |
| `perf.recovery` | ミスから止まらず復帰する能力 |
| `perf.anxiety` | 演奏不安の管理 |
| `perf.focus` | 集中の持続 |

> **これがブートキャンプの核心です。** 練習室で弾けることと本番で弾けることの差は、技術ではなく本番能力の欠如です。そして本番能力は「本番の再現」でしか鍛えられません。アプリは毎日1回、**録音・一発・やり直し禁止**の通し演奏を強制します。

### 2.9 アンサンブル（`ens`）

`ens.follow`（他者に合わせる）/ `ens.lead`（提示する）/ `ens.listen`（弾きながら聴く）/ `ens.click`（クリック同期）

## 3. 測定可能性の3階層 — 設計上の最重要判断

すべてを自動測定できるふりをしてはいけません。能力ごとに測定手段を明示し、**階層に応じてUIと重み付けを変えます**。

### Tier A — スマホのマイクで自動測定できる

| 指標 | 手法 |
|---|---|
| タイミング偏差（平均・SD） | スペクトラルフラックスによるオンセット検出 → グリッド最近傍との差分 |
| テンポ達成度 | 基準を満たした最高BPM |
| 音程精度（単音） | YIN / McLeod ピッチ検出（E2 82Hz〜E6 1319Hz） |
| 音量の粒立ち | オンセット毎のRMS → 変動係数 |
| 完遂率 | 止まらずに最後まで到達したか |
| 持続劣化率 | 前半と後半の指標差 |

**必須の前提：レイテンシ校正。** マイク入力遅延と出力遅延を測らずにタイミングを測ると、系統誤差が全データに乗ります。初回起動時に「スピーカーから鳴らしたクリックをマイクで録る」往復測定を行い、端末ごとにオフセットを保存します。これを省くと測定値は無意味です。

### Tier B — 録音を残して後から採点

多声部の和音、音色、フレージングなど、自動判定が現実的でない領域。
**毎回録音を保存し、ルーブリック（3〜5項目 × 3段階）で自己採点**します。翌週に聴き返して再採点させることで、`ear.selfmonitor` も同時に鍛えます。

### Tier C — 自己申告

演奏不安、集中、表現の意図。5段階のチェックインのみ。
**Tier C の数値をレーダーチャートで Tier A と同列に並べてはいけません。** 見た目の進歩を捏造するアプリになります。

## 4. データモデル

既存の「静的JSON + 検証スクリプト」方式をそのまま拡張します。GitHub Pages で完結する強みは維持します。

```
data/
  abilities.json          能力タクソノミー（ID・ドメイン・10段階の到達基準）
  drills/NNN.json         ドリル定義
  repertoire/NNN.json     曲（楽譜・暗譜状態・維持スケジュール）
  programs/NNN.json       週次プログラム（ブートキャンプ本体）
  assessments/NNN.json    昇級テスト
  lessons/ phrases.json   （既存。ドリルへ順次移行）
```

### 4.1 ドリル定義

ドリルは「何を鍛え、何を測り、どう上げるか」を自己記述します。処方エンジンはこれだけを読みます。

```json
{
  "id": "rh-alternation-evenness",
  "title": "i–m 交互運指の粒立ち",
  "trains": [
    { "ability": "tech.rh.independence", "weight": 1.0 },
    { "ability": "time.precision",       "weight": 0.4 }
  ],
  "tier": "A",
  "measure": {
    "type": "onset-grid",
    "primary": "time.sd_ms",
    "secondary": ["dynamics.cv", "completion"],
    "criterion": { "time.sd_ms": "<=18", "dynamics.cv": "<=0.15", "completion": "==1" }
  },
  "progression": {
    "variable": "bpm",
    "start": 60, "step": 4, "max": 168,
    "advance": "2-consecutive-clean",
    "regress": "3-consecutive-fail"
  },
  "dose": { "minutes": 4, "sets": 3, "restSec": 30 },
  "score": { "phraseId": "c-major-eight-bars" }
}
```

**`criterion` を満たさない限りテンポは上がりません。** 精度を犠牲にした速度は能力ではなく癖であり、後で剥がすのに数倍の時間がかかります。これをアプリが機械的に強制することが、独学者にとって最大の価値です。

### 4.2 訓練者の状態（端末内）

```json
{
  "schemaVersion": 1,
  "abilities": {
    "tech.rh.independence": { "level": 4.2, "confidence": 0.8, "lastMeasured": "2026-08-29" }
  },
  "drills": {
    "rh-alternation-evenness": { "bpm": 84, "cleanStreak": 1, "dueDate": "2026-08-31" }
  },
  "sessions": [
    { "date": "2026-08-29", "minutes": 42, "items": [
      { "drillId": "rh-alternation-evenness", "bpm": 84,
        "metrics": { "time.mean_ms": -3.1, "time.sd_ms": 16.4, "dynamics.cv": 0.12 },
        "passed": true }
    ]}
  ],
  "recordings": ["rec-2026-08-29-take1"]
}
```

**この状態は1年分の訓練記録になります。localStorage だけに置くのは危険です。**
- iOS の PWA はストレージが退去されうる
- 端末を替えたら全消滅
- バックアップ手段が無い

→ **フェーズ1の時点で JSON エクスポート／インポートを実装します。** 後回しにすると、失った時点で取り返しがつきません。保存先は IndexedDB（録音バイナリを持つため）とし、`localStorage` は設定のみに使います。

## 5. エンジン層の分離 — 今の構造では拡張できない

現在 `phrase.js` は 700行で、データ取得・音楽モデル・SVG製譜・音源合成・スケジューリング・UIを全て抱えています。
`guitar.js` はメトロノームのスケジューラを別実装で重複して持っています。

ドリルが40種類に増えると、この形では毎回スケジューラと製譜器を書き直すことになります。**先に切り出します。**

```
core/                      画面を知らない。純粋なロジック
  clock.js                 先読みオーディオスケジューラ（現在2箇所に重複）
  synth.js                 メロディ／伴奏／ドラムの音源
  pitch.js                 YIN ピッチ検出
  onset.js                 スペクトラルフラックス オンセット検出
  calibration.js           入出力レイテンシ校正
  music.js                 音名・音程・調号・TAB↔音高 変換（現在 phrase.js に散在）
  notation.js              五線譜SVG製譜（現在 phrase.js に埋没）
  metrics.js               演奏 → 指標（偏り／ばらつき／CV）
  prescribe.js             処方エンジン
  store.js                 IndexedDB 永続化・エクスポート

modes/                     画面。core を組み合わせるだけ
  today.js  drill.js  score.js  repertoire.js  record.js  assess.js
```

依存の向きは `modes → core` の一方向のみ。`core` は DOM を触らないので、Node で単体テストできます（現在はブラウザテストでしか検証できません）。

**移行順序：** `clock.js` の重複解消 → `music.js` / `notation.js` の抽出 → 以降の新規実装は core 前提。既存3画面は動いたまま段階的に置き換えます。

## 6. 処方エンジン — 「今日やること」の決め方

毎朝、アプリが訓練者の状態から当日のセッションを組み立てます。**選択肢は出しません。** 選択の余地は意志力を消費し、弱点の回避を許します。

セッションは筋力トレーニングと同じ枠構成を取ります。

| 枠 | 時間比 | 選び方 |
|---|---|---|
| **ウォームアップ** | 10% | 固定。脱力と可動域。故障予防のため省略不可 |
| **弱点** | 30% | 能力レーダーの下位2ドメインから。逃げられない場所 |
| **進行** | 30% | 次の昇級テストに直結するドリル |
| **維持** | 20% | 間隔反復で期限が来たドリル・曲 |
| **本番** | 10% | **録音・一発・やり直し禁止**の通し1回 |

維持枠の間隔反復は、達成度に応じて再出題間隔を伸縮させます（1日 → 3日 → 7日 → 16日 → 35日。失敗時は1段階戻す）。曲のレパートリーにも同じ規則を適用し、`rep.maintenance` を自動で管理します。

**本番枠を最後に固定するのが設計上の要点です。** 疲れて集中が切れた状態で一発録りをするのは、本番条件に近く、`perf.robustness` と `perf.recovery` を鍛える唯一の現実的な手段です。快調なときだけ録音しても本番能力は上がりません。

## 7. 昇級ゲート

日々の数値とは別に、**級位**を置きます。日々の指標が「今日の進み」であるのに対し、級位は「何ができる人になったか」です。

各級は実技試験の集合として定義され、全項目同日中に合格して初めて昇級します。部分合格は繰り越しません。

```json
{
  "id": "grade-05",
  "title": "5級：低音と旋律の分離",
  "requires": [
    { "type": "drill",  "id": "thumb-independence", "bpm": 96, "criterion": "clean" },
    { "type": "sight",  "difficulty": 3, "measures": 8, "criterion": "completion==1 && time.sd_ms<=35" },
    { "type": "piece",  "fromRepertoire": 1, "memorized": true, "criterion": "no-stop" },
    { "type": "ear",    "task": "interval-id", "accuracy": 0.9 },
    { "type": "improv", "bars": 16, "over": "Am-F-C-G", "rubric": "coherence>=2" }
  ]
}
```

初見・耳・即興を必須項目に混ぜるのが重要です。技術ドリルだけで昇級できる設計にすると、訓練者は必ず得意な技術ドリルに時間を寄せ、職業演奏家に必要な能力の半分が育ちません。

## 8. 画面構成

現在の3モードを6画面へ再編します。

| 画面 | 役割 |
|---|---|
| **今日** | 処方されたセッション。上から順に消化するだけ。開始ボタンと残り時間 |
| **ドリル** | 測定面。譜面＋メトロノーム＋マイク＋即時フィードバック（走り／もたり／揺れ） |
| **譜面** | 現行 `phrase.html` の一般化。読譜・初見・レパートリー閲覧 |
| **レパートリー** | 曲の暗譜状態と維持ローテーション。「どの小節から？」の抜き打ち |
| **記録** | 能力レーダー、指標の時系列、自己ベスト、連続日数、録音一覧 |
| **昇級** | 現在の級と次級の要件、各項目の合否状況 |

「記録」画面が動機づけの中心になります。**Tier A の実測値と Tier C の自己申告は視覚的に区別**し、後者を薄く／破線で描きます。数字の出所が曖昧なグラフは、そのうち信用されなくなります。

## 9. 実装フェーズ

各フェーズは単体で価値があり、途中で止めても壊れません。

| | 内容 | 完了の定義 |
|---|---|---|
| **P0** | 不具合修正、`core/` へのエンジン抽出、`clock.js` の重複解消 | 既存3画面が core 経由で動作 |
| **P1** | マイク入力、レイテンシ校正、オンセット検出、**1本のドリルを端から端まで測定**、JSONエクスポート | 1ドリルで偏り・ばらつきが数値で出る |
| **P2** | `abilities.json` 整備、`drills/` を10本、IndexedDB、記録画面（レーダー＋時系列） | 弱点が見える |
| **P3** | 処方エンジン、間隔反復、「今日」画面 | 毎朝メニューが自動生成される |
| **P4** | ピッチ検出、レパートリー管理、録音保存、本番枠 | 一発録りが日課になる |
| **P5** | 昇級ゲート、初見生成、耳トレ、即興ルーブリック | 級位で進捗が語れる |

**P1 を最優先にします。** 測定が無いまま教材を増やすのは、現状の延長でしかありません。ドリル1本でも数値が出れば、そこから先は同じ器に流し込む作業になります。

## 10. 技術的前提とリスク

| 事項 | 内容と対処 |
|---|---|
| **レイテンシ校正** | 未校正のタイミング測定は系統誤差を含み無意味。P1で必須実装 |
| **マイク権限** | HTTPS必須（Pages は該当）。ユーザー操作起点が必要。iOS はページ遷移で再要求されうるので、SPA的な画面遷移を検討 |
| **和音のピッチ検出** | 多声部の自動採譜は現実的でない。**測定対象のドリルは単音で設計する**。和音は Tier B（録音＋ルーブリック）へ回す |
| **データ消失** | iOS PWA のストレージ退去、端末更新。P1でエクスポート、将来は任意のクラウド同期（アプリ本体は静的のまま維持） |
| **バックグラウンド抑制** | タブ非アクティブ時に `setInterval` が絞られる。オーディオクロック基準の実装なら影響を受けない（P0で統一済み） |
| **アコースティックの環境ノイズ** | オンセット検出はノイズに弱い。入力レベル調整とノイズフロア推定を `onset.js` に持たせる |
| **測りすぎ** | 全ドリルを毎回測ると練習が計測作業になる。**1セッションで測るのは3〜4項目**に絞る |

## 11. 意図的に作らないもの

範囲を守ることが、このアプリが完成する条件です。

- **多声部の自動採譜・自動採点** — 精度が出ず、誤判定は訓練者の信頼を破壊する
- **動画解析によるフォーム判定** — 静的サイトの範囲を超え、精度も不十分
- **SNS・ランキング・他者比較** — 動機づけを外部化すると、独習の継続には逆効果
- **音楽理論の網羅的な教科書機能** — 訓練に必要な範囲のみを、ドリルの文脈で提示する
- **業務面（営業・録音技術・機材）** — 演奏能力に範囲を限定する
